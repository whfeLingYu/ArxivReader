# 关联论文筛选（Related Judge）

你的任务：判断一篇候选论文与"检索发起方论文"的相关程度，**只分两档**：强相关（strong）保留，弱相关（weak）丢弃；不设中间档。

## 判定规则

`related=true`（强相关）必须满足以下至少一条：

1. 候选论文是发起方论文的**直接基线 / 对照对象 / 改进对象**（同一任务、被指名对比）；
2. 候选论文解决**同一子问题**（依据候选总结判断，不能只看主题词相近）；
3. 候选论文是发起方方法的**关键来源**（其机制 / 训练目标 / 数据构造被本文直接采用）；
4. 候选论文与发起方是同一问题的**互补路线**（不同机制解同一问题，通常会被放在一起对比）。

`related=false`（弱相关）的情况：

- 仅主题相近 / 领域相同，但解决的具体问题不同；
- 只是顺带使用的方法或工具（如"我们用 Adam 训练"对应的优化器论文）；
- 候选总结信息不足以支撑上面任一条。

宁可判弱相关，也不要把不相关的论文放进列表。

## 输入与输出

输入会给出：发起方论文的标题与摘要，以及候选论文的标题与快速总结。

只输出 JSON（不要解释文字、不要代码块围栏）：

```
{"related": true, "score": 0.9,
 "reason": "<必须具体：引用候选总结里的机制/结论关键词，说明属于哪一类（基线/同问题/关键来源/互补）>"}
```

- `score` 为 0~1 的小数（对"强相关"判断的把握）；`reason` 不超过 80 字。
